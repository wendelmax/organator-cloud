# Release 2.1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Align the complete first-party npm monorepo with the closed milestone 5 version `2.1.0` and publish the version metadata through a reviewed PR.

**Architecture:** Use npm workspace-aware versioning so manifests and lockfile metadata are updated by the package manager rather than by independent manual edits. Validate that only first-party version metadata changes and keep tagging as a post-merge operation.

**Tech Stack:** npm 11 workspaces, Node.js 24, Turborepo, GitHub CLI.

## Global Constraints

- All seven first-party manifests must report exactly `2.1.0`.
- Dependency specifications and resolved dependency versions must not change.
- Do not create or move tag `v2.1.0` before the version PR is merged.
- CI lint and build must pass before merge.

### Task 1: Update workspace version metadata

**Files:**
- Modify: `package.json`
- Modify: `package-lock.json`
- Modify: `apps/backoffice-web/package.json`
- Modify: `apps/control-plane-api/package.json`
- Modify: `apps/provisioner-worker/package.json`
- Modify: `packages/cloud-providers/package.json`
- Modify: `packages/core-models/package.json`
- Modify: `packages/ui/package.json`

**Interfaces:**
- Consumes: npm workspace definitions from the root `package.json`.
- Produces: consistent `version: 2.1.0` metadata in every first-party manifest and its lockfile workspace entry.

- [ ] **Step 1: Prove the repository is not yet consistently versioned**

Run:

```bash
node -e "const fs=require('fs');const paths=['package.json','apps/backoffice-web/package.json','apps/control-plane-api/package.json','apps/provisioner-worker/package.json','packages/cloud-providers/package.json','packages/core-models/package.json','packages/ui/package.json'];const bad=paths.filter(p=>JSON.parse(fs.readFileSync(p)).version!=='2.1.0');if(bad.length){console.error(bad.join('\n'));process.exit(1)}"
```

Expected: exit `1`, listing manifests that are not `2.1.0`.

- [ ] **Step 2: Apply the version through npm workspaces**

Run:

```bash
npm version 2.1.0 --no-git-tag-version --workspaces --include-workspace-root
```

Expected: npm updates the root, all six workspaces, and matching `package-lock.json` package metadata without creating a Git tag.

- [ ] **Step 3: Verify manifest and lockfile consistency**

Run:

```bash
node -e "const fs=require('fs');const paths=['package.json','apps/backoffice-web/package.json','apps/control-plane-api/package.json','apps/provisioner-worker/package.json','packages/cloud-providers/package.json','packages/core-models/package.json','packages/ui/package.json'];for(const p of paths){if(JSON.parse(fs.readFileSync(p)).version!=='2.1.0')throw new Error(p)}const lock=JSON.parse(fs.readFileSync('package-lock.json'));for(const p of paths){const key=p==='package.json'?'':p.replace('/package.json','');if(lock.packages[key]?.version!=='2.1.0')throw new Error('lock:'+key)}"
```

Expected: exit `0` with no output.

- [ ] **Step 4: Confirm no dependency drift**

Run:

```bash
git diff -- package.json package-lock.json apps/backoffice-web/package.json apps/control-plane-api/package.json apps/provisioner-worker/package.json packages/cloud-providers/package.json packages/core-models/package.json packages/ui/package.json
```

Expected: only `version` fields change; dependency ranges, resolved versions, integrity hashes, and package names remain identical.

- [ ] **Step 5: Commit the version metadata**

```bash
git add package.json package-lock.json apps/backoffice-web/package.json apps/control-plane-api/package.json apps/provisioner-worker/package.json packages/cloud-providers/package.json packages/core-models/package.json packages/ui/package.json
git commit -m "chore(release): bump project version to 2.1.0"
```

- [ ] **Step 5: Post-merge release operation**

After explicit merge confirmation:

```bash
git switch main
git pull --ff-only origin main
git tag -a v2.1.0 -m "v2.1.0"
git push origin v2.1.0
gh release create v2.1.0 --title "v2.1.0" --generate-notes
```

Expected: local `main` matches `origin/main`; immutable tag and GitHub release point at the merged version commit.
